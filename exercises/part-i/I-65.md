**Input:** `t1(listing_id, home_id, status)` (9 rows).

## Solution

```sql
WITH a AS(
SELECT *,sum(status IN('New Listing','Relisted')) OVER(
ORDER BY listing_id ROWS UNBOUNDED PRECEDING) global_id
FROM t1)
SELECT listing_id,home_id,status,max(CASE WHEN status IN('New Listing','Relisted') THEN global_id END) OVER(PARTITION BY home_id
ORDER BY listing_id ROWS UNBOUNDED PRECEDING)
FROM a;
```

**Result and verification:** result 1: 9 rows. [[1,"Home A","New Listing",1],[2,"Home A","Pending",1],[3,"Home A","Relisted",2],[4,"Home B","New Listing",3],[5,"Home B","Under Contract",3],[6,"Home B","Relisted",4]] … (see the report for the full output)

## Explanation

**Method and assumptions:** each New Listing or Relisted event gets a new global key. Later events for the same home inherit it even if other homes have events in between. An event without an earlier opening has a NULL group.

**Edge cases and trade-offs:** with interleaved events, Home A stays in group 2 and Relisted starts group 6 for Home C.
